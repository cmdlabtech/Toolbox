    Setting up credentials

    The report needs two data sources: HPE GreenLake (device inventory + subscription keys) and Aruba Central (AP up/down status and names). Everything is read-only. Use the Instances sidebar to keep one credential set per customer, workspace, or region. Open a section below for the part you need.

    HPE GreenLake credentials Always required
    1. Sign in at common.cloud.hpe.com and pick the workspace that owns your devices.
    2. Go to Manage Workspace → API → Create Credentials.
    3. Choose the workspace, name the credential, and copy the Client ID and Client Secret into the Basics step.
    4. The credential needs read access to Devices and Subscriptions (Observer role is enough — but Detach needs Operator; see below).
    New Central GreenLake-native Central

    Is this me? You open Central from the GreenLake portal (common.cloud.hpe.com) and your Central has the new left-hand navigation. Your API base URL looks like https://us1.api.central.arubanetworks.com.

    1. Find your cluster: in New Central go to the API documentation page (or check the region shown for your Central service in GreenLake) — the base URL is https://<cluster>.api.central.arubanetworks.com, e.g. us1, eu1, de1.
    2. Leave “Use my GreenLake credentials” ticked — New Central accepts GreenLake platform tokens, so no extra setup is needed.
    3. Alternatively, create a dedicated API client in New Central (Global Settings → API → Create personal API client) and enter its ID/secret instead.
    Classic Central Classic Aruba Central

    Is this me? You sign in directly at central.arubanetworks.com. Your API gateway looks like https://apigw-prod2.central.arubanetworks.com.

    1. Find your gateway: Central UI → Organization → Platform Integration → REST API (the datalist in the form has common regions).
    2. Quick test: API Gateway → System Apps & Tokens → Generate Token → paste it as the access token. It expires after ~2 hours.
    3. Repeat runs: API Gateway → My Apps & Tokens → add an app, then copy its Client ID, Client Secret, and the refresh token. The tool refreshes automatically and stores the rotated token back into this instance.
    Detaching subscriptions & ignoring APs

    In the Action needed tab of a generated report, each Down AP holding a subscription has two buttons:

    1. Detach removes the subscription assignment in GreenLake (after a confirmation), freeing the seat. Your GreenLake credential needs write access to Devices (Operator role or higher) — an Observer credential can only read. GreenLake processes the change asynchronously, so allow a minute before it shows in a fresh report.
    2. Ignore marks the AP as down temporarily for the current instance: it moves to an “Ignored” list and stops being counted as a detach candidate in future reports, until you Unignore it. The ignore list is saved with the instance in this browser.

    The Detach button also appears in Mismatches → In GreenLake but not in Central for devices that hold a subscription even though Central has never seen them (spares, RMA'd units).

    These buttons only exist in the app — a downloaded report is a static snapshot and cannot change anything.

    Adding subscription keys & devices

    The Add inventory tool registers new subscription keys and new devices in the current instance's GreenLake workspace in one action — keys one per line, devices as serial,mac lines, or upload the same CSV GreenLake provides for device import (Serial_No,MAC_Address,…). GreenLake processes additions asynchronously and accepts up to five devices per API call (the tool batches larger lists automatically), so give a large batch a minute before regenerating the report. The GreenLake credential needs Operator role or higher.

    Where do credentials go?

    Saved instances — including their secrets — live unencrypted in this browser's local storage on this device, so anyone who can open this browser profile could read them; delete an instance (🗙 in the sidebar) to remove it. When you generate a report, credentials are sent to this app's server (a Cloudflare Worker) over HTTPS, used for the HPE/Aruba API calls, and discarded — nothing is stored server-side. Each person uses their own credentials, so another visitor to this URL cannot see your data or act on your workspace. This is a shared public URL: don't paste credentials on a device or browser profile you don't trust.

    The generated report is a self-contained HTML file with the data baked in — no credentials inside — so that file is safe to share.
